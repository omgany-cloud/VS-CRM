## Что пользователь решил

Главный рабочий раздел — «Задачи», общий чат каждой задачи объединяет взаимодействие по CRM.
Задачи бывают свободными и связанными с процессами. Связанная задача называется «Подзадача»;
переписка и права у задач остаются отдельными. Пользователь просит простой интерфейс без лишних форм.

- Сообщения всех участников на одинаковом фоне, без отдельного цвета своих сообщений.
- Автор, аватар и время видны; выбранные упоминания выделяются цветом текста.
- Подсказки сотрудников появляются при наборе имени, символ @ не обязателен.
  Выбор имени и отправка сообщения добавляют подходящего сотрудника в чат.
  Просто текстовое имя без выбора подсказки никого не приглашает.
- Добавление в чат не назначает согласующим. Формальные решения согласования отдельны.
- Согласование по выбранным сотрудникам параллельное, без переключателя режима для пользователя.
- Ответ на сообщение — цитата в том же чате, с переходом к исходному сообщению.
- Справа свойства задачи, участники, согласующие, связи, а ниже «Файлы».
- Переименование прямо в заголовке: клик, ввод; Enter или выход из поля сохраняет, Escape отменяет.
  Никакого отдельного окна и кнопки «Сохранить» для переименования.
- Из корзины разрешено удалять навсегда с одним подтверждением.

## Что реализовано в текущем пакете

1. Статусы задач: в работе, завершена, корзина; восстановление, срок, ответственный,
   сортировка по активности/сроку/созданию/названию, личные непрочитанные сообщения.
2. Макет: список задач слева, переписка в центре, сворачиваемые свойства справа.
3. Компактные сообщения, авторы и даты, подсказки сотрудников, ответы с серверной проверкой
   принадлежности исходного сообщения. Черновики текста, вложений и ответов сохраняются при переключении.
4. Каталог файлов всей истории задачи, а не только текущей страницы сообщений;
   поиск и защищённое скачивание. У договора также показываются его редакции.
5. Переименование существующих задач. При обновлении чата ввод не теряется;
   при ошибке остаётся черновик, конфликт версии требует повторного явного сохранения.
   Название меняется в списке и связях. У договора меняется название задачи, не реквизиты договора.
6. Окончательное удаление из корзины: атомарно удаляются сообщения, вложения, участники,
   отметки прочтения и связи удаляемой задачи. Соседние задачи и записи CRM сохраняются.
   Договор, редакции и история согласования не удаляются.
7. Проверки текущих прав, версии, повторной доставки запросов; журнал действий.
   Активное согласование запрещает закрытие, помещение в корзину и окончательное удаление задачи.

## Важные детали реализации

- `discussion_task_state`: состояние, срок, версия, ответственный, переопределение названия,
  отметка `purged_at` для удалённой задачи договора.
- `discussion_task_commands`: ключи запросов и результаты, предотвращающие повторные изменения.
- `discussion_task_reads`: личные отметки прочтения.
- В обеих таблицах сообщений есть `reply_to_id`. Вложения хранятся BLOB в `discussion_files`.
- `POST /api/discussions/:kind/:id/state`: rename, due, assign, complete, reopen, trash, restore.
- `DELETE /api/discussions/:kind/:id`: удаление навсегда; тело expectedVersion + requestKey.
- Свободная задача удаляется из БД. Для договора остаётся служебная отметка, иначе задача,
  вычисляемая из существующего договора, появилась бы снова после обновления списка.
- Новое согласование после удаления чата создаёт пустую задачу в той же транзакции.
  История удалённого чата не восстанавливается. Повтор старого DELETE не удаляет новую задачу.
- Связь другой задачи непосредственно с договором сохраняется; связь с удалённым чатом снимается.
- Журнал действий, квитанции повторных запросов и резервные копии не очищаются удалением задачи.
- Управление свободной задачей доступно создателю; задачей договора — пользователю с manageContracts.
  Права и компания проверяются сервером. readOnly допускает лишь собственную отметку прочтения.
